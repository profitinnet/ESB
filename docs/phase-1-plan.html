Интеграционная шина. Первый этап

План работ, не отчёт о уже сделанных маршрутах. 5 октября 2026. Сервер dwh-proc01. Общий план MVP — в файле mvp-plan.pdf.

Слова на этой странице. Брокер — программа, которая хранит сообщения и отдаёт их подписчикам. Здесь это Redpanda. Топик — именованный канал сообщений одного вида. Эмулятор — небольшая программа с теми же запросами, что у настоящей системы, без её учёта и без электронной подписи. DLQ — отдельный топик для сообщений, которые не удалось обработать. Service Layer — штатный сетевой вход SAP Business One. Сеть контейнеров — способ программам в Docker обращаться друг к другу по имени, не через внешний адрес сервера.

1. Что входит в этап

Только обмен между четырьмя стендовыми программами: SAP Business One, 1С, EDIN и Вчасно. Боевые системы не подключаем. Почему: для проверки маршрута не нужны их адреса и пароли, а ошибка в маршруте видна сразу.

Вне этапа: помощник на базе ИИ, дашборды, смена режима Redpanda, боевые адреса, Kafka как брокер наших маршрутов.

Чужие контейнеры на сервере тоже не трогаем. Почему: сервер общий, а смена режима Redpanda перезапустила бы уже работающее хранилище.

3. Куда встанет наш запуск

Новый набор контейнеров называется ibus. Его подключаем к уже существующей сети redpanda_default. Camel этого этапа обращается к redpanda:9092, а не к localhost:19092. Почему: адрес localhost внутри другого контейнера указывает на него самого, а не на Redpanda.

Это отдельный Camel, не учебный на порту 8880. Порт будет другой. Почему: 8880 уже занят проверкой hello. Запуск маршрутов — из текстового файла YAML той же программой Camel JBang 4.22.1, которая уже стоит на сервере. Отдельную сборку проекта не делаем. Почему: вторая сборка Camel для той же задачи не нужна.

Исходники остаются в проекте на этом компьютере. На сервер, в каталог /opt/ibus, копируется только то, что нужно для запуска. Почему: правка маршрута должна оставаться в проекте, а не только в файле на сервере.

4. Три потока

1. Входящий документ. Эмулятор EDIN → топик doc.edin.received.v1 → Camel → заказ в эмуляторе SAP B1 → топик erp.order.upserted.v1.

2. Статус подписи. Эмулятор Вчасно → топик doc.vchasno.status.v1 → Camel обновляет тот же заказ в эмуляторе SAP B1.

3. Передача в 1С. Топик erp.order.upserted.v1 → Camel → эмулятор 1С.

Если SAP B1 отверг сообщение, оно уходит в DLQ. Следующий правильный документ при этом проходит.

ЭмуляторЧто должен уметьУспех
SAP Business OneВход Login, создание и чтение заказа, понятная ошибка проверкиCamel получил номер документа либо ошибка лежит в DLQ
1СПриём документа в нашем JSONВ ответе номер. Повтор того же id не создаёт второй документ
EDINСписок новых документов и подтверждение, что документ забран. Сертификаты не имитируемСобытие опубликовано в doc.edin.received.v1
ВчасноДокумент, смена статуса, вызов нашего адреса. В событии только статус, не подписьСтатус приходит в doc.vchasno.status.v1

Повтор того же id не создаёт второй заказ и второй документ 1С. Почему: после сбоя шина может прислать сообщение ещё раз, и документ не должен задвоиться. Эмулятор помнит id и возвращает уже выданный номер. Отдельную базу для этого в этап не добавляем.

5. Контракт сообщения

Оболочка сообщения — формат CloudEvents. Поля: id, source (кто отправил), type (что за событие), time, subject, correlationid. subject — номер документа, по нему держится порядок сообщений одного заказа. correlationid — общий номер цепочки, чтобы найти документ на всех шагах. Поле трассы и сборщик трасс в этот этап не входят.

Новые топики, у каждого три части и одна копия:

  • doc.edin.received.v1
  • doc.vchasno.status.v1
  • erp.order.upserted.v1
  • для каждого из них топик ошибок с приставкой dlq.

Три части у топика нужны, чтобы позже добавить читателей без переименования. Одна копия — потому что сервер один. Топик orders не изменяем. Почему: его уже пишет учебный Connect.

Шаблоны полей тела кладём в проект как JSON Schema. В каталог схем Redpanda их регистрируем после первого успешного прохода, не раньше. Почему: иначе зафиксируем черновик.

6. Что появится в проекте

  • compose/docker-compose.yml — четыре эмулятора и отдельный Camel в сети redpanda_default.
  • emulators/ — один образ программы и четыре службы: SAP B1, 1С, EDIN, Вчасно.
  • camel/routes/ — три маршрута в текстовых файлах YAML.
  • contracts/ — примеры трёх сообщений и шаблоны полей.
  • Короткая пометка в общем плане: этап 1 идёт отдельным Camel, учебный маршрут на порту 8880 не заменяется.

7. Когда этап считаем готовым

  • Документ из эмулятора EDIN становится заказом в эмуляторе SAP B1, и в erp.order.upserted.v1 есть одно сообщение.
  • Статус из Вчасно меняет этот заказ, а не создаёт новый.
  • Эмулятор 1С принимает документ один раз. Повтор того же id возвращает тот же номер.
  • Неверный заказ виден в DLQ, следующий верный проходит.
  • В Kafka на порту 9094 новых топиков этапа нет. Учебные hello и топик orders на месте.
